# v0.3.0 — 可交付

**目标**：人类入口与界面接入，玩法可完整走完一局，参数可扫描调校，大模型接文本层——对局从「可对弈」变成「可交付」。

**依赖**：v0.2.2。

## 待做

- [ ] 人类命令入口：友方决断相位接受人类输入覆盖自动决断（输入格式与自动决断输出完全一致）；`play` 命令行对局；Flutter 端从直接调内部方法改为只调引擎公开入口
- [ ] 上帝视角玩法作为第二个入口接入：绕过指挥部直达引擎，两种玩法共用同一套结算
- [ ] 合流三栏指挥部界面（`headquarters_screen.dart`）为决策入口，决心卡循环接进去——原 studio v0.2.0 方向在此收口
- [ ] 情报系统：IntelGenerator（真实状态 → 过滤 → 玩家所见）、侦察请求（延迟 1-2 回合）、情报看板（时效 + 可信度标记）；推演模式保持全知，剧本模式启用情报
- [ ] LLM 参谋长：理解意图接口、参谋翻译器模板两级展开 + 回执、结构化追问（敌军建制评估卡：估计/置信度/出处）；大模型只接两处——战报润色与参谋对话
- [ ] 开发仪表盘（信念轨迹、通信时间线、决策追踪、战损分布）：只读档案不做活体查询；命令行文本形态先验收，可视化算加分项
- [ ] 参数扫描调参：失真率、谨慎度、信念重算周期；结果存档跨版本对比；每周重演金标准对局
- [ ] 三线后果（军事/消耗/政治）填充 v0.2.1 预留的后果槽位；三线数值进参数表
- [ ] 补给深化：连通性判断升级为完整补给模型，敏感性纳入常规扫描
- [ ] 人类协议验收：本人对局（禁真相入口，实时记困惑清单——表达不出的命令/误读的战报/失衡的节奏）；新人复述（未参与者只读战报打半局）；界面对照表（每条界面对应哪个命令行输出）
- [ ] 文档同步：现状文档改按版本记述；架构说明书升版

## 验收

- 人经命令行打完整一局，档案齐备
- Flutter 端两种玩法均可运行
- 四张仪表读档案出图，开发期每周被使用
- 一轮扫描存档与上周曲线可比
- 三线后果在战报中可见；LLM 接入后全量断言重跑，统计分布不漂移
- 首次完整通关；困惑清单形成下一轮输入；对照表覆盖全部界面信息

## 风险与未达标处理

- 最大风险是范围蔓延 → A 类验收通过即封版，剩余项进待办不阻塞关闭
- 仪表盘打磨失控 → 文本形态先验收
- 命令接口冻结：新功能只加命令，不改已有命令
