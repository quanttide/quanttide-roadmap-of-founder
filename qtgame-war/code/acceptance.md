# 验收系统的落地顺序

**日期**：2026-10-25

**覆盖阶段**：M1 之前到交付之后

## 1. 文档范围

验收系统交付的是一套能证明游戏对了的工具链：一个命令行工具、一套断言、一批金标准夹具、一份人类测试清单。

它与本体并行，节奏领先半步：本体换真实现之前，对应的验收能力先长出来等着。

## 2. 顺序与达成标志

### 2.1 M1 之前：夹具与金标准（1 周）

这一步先造答案，后面每一步都拿真结果与它比对。

- 金种子集：固定种子的随机流，全项目共用一份。
- 微型想定三到五个：两单位对撞、迂回包抄、隔河对峙、通信延迟，每个手写期望结果。
- 命令样例：契约两侧各一份合法与非法样本。
- 校验命令：只验格式，不验内容。

达成标志：夹具过评审，每个期望结果说得出为什么对；校验命令拦住全部非法样本。

### 2.2 M1：命令行骨架与自动断言（1–2 周）

交付 new、order、step、report、diff 五个子命令。

断言分四类：

- 接通：按开局、下令、推进、读报走完一个回合。
- 确定性：同种子跑两次，比对输出为空。
- 契约：每回合进出的文件通过校验。
- 负向：喂非法命令，系统拒绝并给出可读错误。

四类断言挂提交钩子。

达成标志：换掉任一侧桩，断言不改仍全绿。

### 2.3 M2：回归与批量（3–4 周，随真引擎渐增）

- 回归：微型想定逐个跑，事件流与手写期望比对。
- 批量：一百个种子出统计，先记录不设限。
- 扩容：每实现一个机制补一个夹具。

达成标志：金种子全绿进 CI；每个已实现机制至少一个专用夹具；批量稳定产出统计。

### 2.4 M3：迷雾与 AI 断言（2–3 周）

- 迷雾断言：报告与真相比对，不在场事件不可见，迟到报告符合通信排程，假情报影响信念方向。
- 可解释断言：敌军每个决策带情报出处与性格权重，脚本可追溯。
- 性格扫描：批量扫谨慎度与冒进度，人工读结局分布。
- 对称性审查：敌军与玩家读同一份投影、走同一份契约，真相不进它的决策记录。

达成标志：故意注入的三处泄露都能被抓住；决策全部可追溯；对称性审查通过。

### 2.5 M4：人类协议（2 周）

- 本人对局：禁用真相入口，只用报告、地图与追问；实时记困惑清单，分三类——表达不出的命令、误读的战报、失衡的节奏。
- 新人复述：未参与者只读战报打半局，复述对了算过。
- 界面对照表：界面每条信息对应哪个命令行输出，逐条登记。

达成标志：首次完整通关；困惑清单形成下一轮输入；对照表覆盖全部界面信息。

### 2.6 交付后：值守

- 大模型接入后全量断言重跑，分布不漂移即通过，漂移即违规。
- 批量、比对、重演成为日常。
- 命令接口冻结，新功能只加命令，不改已有命令。

达成标志：连续若干轮迭代，断言不改仍全绿。

## 3. 后置代价

夹具晚一周，本体的第一版引擎就只能对着感觉调，之后每改一次机制都要补一次历史答案。

自动断言全绿之后仍要有人完整打一局。表达不出的命令、误读的战报、失衡的节奏，没有断言能抓；这层若省掉，验收只剩格式。

## 4. 纪律

- 金标准人工把关：夹具可以脚本生成，期望结果必须有人复核。
- 验收与本体同步交付：本体换真实现时验收能力不到位，视为该阶段未完成。
- 人类协议每轮迭代固定重跑，困惑清单与自动断言同等对待。
