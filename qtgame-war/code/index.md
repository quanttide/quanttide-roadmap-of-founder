# 迷雾中的司令部

先做确定性底座，再做可审计的回合档案，然后把认知层接上，最后接人类与界面。四段依次验收，前一段不达标不进入下一段。

## 顺序与理由

第一段让引擎可复算。同一组命令配同一个随机种子重跑两遍，事件流要逐字节一致，引擎也不能依赖界面层。排在第一的理由很直接：后面每一段都靠重跑比对来验收，确定性破了，所有断言都站在沙子上，越往后返工越贵。

第二段让对局可复盘。每一回合的指令、事件、情报与决断都要落成档案，事件与报告在关卡处分开：上层只读报告，读不到事件的原始真相。有了档案，才谈得上复盘与定位偏离，也才有办法测量迷雾到底有没有生效。

第三段让两边都能对弈。过滤、延迟、失真、信念重算、参谋翻译逐项接上，敌军指挥与玩家走同一条管线和同一份契约，读的是自己的情报记录，不读引擎真相。这一段是玩法主体，也是最大的不确定项，所以验收不用「打得像不像人」这种主观标准，只用结构性断言。

第四段才接人类与界面。人类的命令可以覆盖 AI 决断，命令式对局先跑通，图形界面收回公开入口，指挥官视角与上帝视角两种玩法都能完整走一局。驱动层换人，机制不变，这是前三段攒下来的自由。

## 每段要过什么

- 可复算：同种子双跑零偏离；改变种子必现偏离，且能指出第一处。
- 可复盘：一局跑完，档案齐备且通过校验；人为注入一处偏移，能定位到具体回合与相位。
- 可对弈：双方 AI 跑完整局；迷雾生效可被外部观察；每一个决断都能回答它当时信了什么。
- 可交付：真人经命令行完整打一局；两种玩法都能运行；档案能回放。

## 全程不变的四条

- 大模型不进结算闭环，只碰事件流之外的文字。
- 界面与测试不得直读引擎真相；迷雾是结构，不是滤镜。
- 参数不进代码，档案只增不改。
- 确定性检查进每次提交，比对不一致即停。
