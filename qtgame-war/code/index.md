# 迷雾中的司令部

先做确定性底座，再做可审计的回合档案，然后把认知层接上，最后接人类与界面。四段依次验收，前一段不达标不进入下一段。

## 顺序与理由

第一段让引擎可复算。同一组命令配同一个主种子重跑两遍，事件流逐字节一致，引擎不依赖界面。排在第一的理由是：后面每一段都靠重跑比对来验收；确定性破了，所有断言都站在沙子上，越往后返工越贵。后置代价：确定性补起来最贵，越往后越难。

第二段让对局可复盘。每回合的命令、事件、情报与决策落成档案，事件与报告在关卡处分开，上层只读报告。没有档案，复盘、定位偏离、测量迷雾都无从谈起。后置代价：档案结构后补要迁移旧档；事件与报告一旦混用，迷雾就难再分开。

第三段让两边都能对弈。过滤、延迟、失真、信念重算、参谋翻译逐项接上；敌军指挥与玩家走同一条管线与同一份契约，只读自己的信念。这一段是玩法主体，也是最大的不确定项，验收不用“打得像不像人”，只用结构断言。后置代价：AI 行为不稳会拖住第四段的人类对局与界面接入。

第四段才接人类与界面。人类命令可以覆盖 AI 决断，命令行对局先跑通，图形界面收回公开入口，互动剧本与上帝视角两种玩法都能完整走一局。后置代价：界面越晚接，越容易在最后才发现命令通道表达不了某种交互。

## 每段要过什么

- 可复算：同种子双跑零偏离；改变种子必现偏离，且能指出第一处。
- 可复盘：一局跑完，档案齐备且通过校验；人为注入一处偏移，能定位到具体回合与相位。
- 可对弈：双方 AI 跑完整局；迷雾生效可被外部观察；每个决断都能回答它当时信了什么。
- 可交付：真人经命令行完整打一局；两种玩法都能运行；档案能回放。

## 全程不变的纪律

- 大模型不进结算闭环，只碰事件流之外的文字。
- 界面与测试不得直读引擎真相；迷雾是结构，不是滤镜。
- 参数不进代码，档案只增不改。
- 确定性检查进每次提交，比对不一致即停。
