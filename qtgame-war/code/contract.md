# 系统契约的落地顺序

**日期**：2026-10-25

**覆盖阶段**：M1 之前的格式冻结，到 M4 的甲板展开

## 1. 文档范围

本文规定契约什么时候定、什么时候改、改到哪一步为止。契约指两层之间的命令格式、事件格式、单位与地形标识、确定性条款；两侧各自的实现不在此列。

契约按独立产品对待：格式先冻结，两侧各自对着桩实现开发，最后合拢。每一步都留下能运行的东西，避免写完文档再等联调。

## 2. 契约条款

- 命令：回合、阵营、命令数组。每条命令含部队、动作、目标、路径约束、时限、中止条件。字段一次定全，宁可先放超集，也不在后期补字段。
- 事件：先列第一版类型表，覆盖机动、接敌、战斗结果、损耗、补给、占领、战报生成。每类定字段，随机记录必须入契约。
- 标识：单位番号与地图节点共用一套编号，先冻结，避免两侧各造一套。
- 确定性：所有随机带种子引用，事件流里不出现没有解释的随机性。

事件类型表是契约的核心，其他条款由它推导，也是开工第一天就能动手的部分。

## 3. 顺序与达成标志

### 3.1 格式冻结（M1 之前，1 周）

产出契约文档、JSON Schema 与校验命令。校验命令只验格式，不验内容。

达成标志：一份手写的命令文件与事件流通过校验，字段没有歧义。

### 3.2 桩实现接通（M1 内，1–2 周）

引擎桩按硬编码规则把命令回显成事件；指挥部桩把一道纵队命令展开成引擎格式，收到事件后弹出一条战报。

达成标志：下令到读报全程无人工干预；同一组命令配同一个种子跑两遍，事件流逐字节一致；任一侧换成真实现，另一侧零改动。

换桩是全程最重要的一次验收。它通过之后，两侧可以并行开发。

### 3.3 真引擎回填（M2，3–4 周）

实现顺序：机动、接敌、战斗、损耗与补给、撤退与溃散。每实现一类结算，对照类型表回填字段；发现缺字段或粒度不对，在 M2 内改掉。

达成标志：金种子下双 AI 跑五十局，统计分布稳定；事件流里没有未定义类型。

### 3.4 认知模块接入（M3，2–3 周）

指挥部一侧接上过滤、延迟、失真、信念重算；敌军 AI 读自己的信念做决策，与玩家走同一份契约。

达成标志：同一局导出真相与玩家所见两份记录，人工比对能指出迷雾生效；敌军每个决策能回答当时信了什么。

### 3.5 甲板展开（M4，2 周起）

契约不再变化，三档甲板归界面层处理。命令翻译从条件分支换成模板两级展开。

达成标志：同一局中途切换甲板，命令展开与战报投影衔接无误；双 AI 跑一千个种子不出现未处理异常。

## 4. 后置代价

M2 是格式的最后修订窗口。进入 M3 之后改一个字段，两侧都要同步改桩，代价按两侧代码量计。宁可把改动压到下一个版本，也不在半路开口子。

标识体系若拖到实现中期才定，番号与地图节点会被写进想定、档案与界面三处，改动要同时迁移三份数据。

## 5. 纪律

- 契约变更走版本号，冻结后按变更记录逐条发布。
- 确定性检查进每次提交，比对结果不为空即停止合并。
- 大模型只碰事件流之外的文本层，不进结算。
