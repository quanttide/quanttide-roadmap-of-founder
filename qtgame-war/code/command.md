# 指挥部侧的落地顺序

**日期**：2026-10-25

**覆盖阶段**：M1 至 M4，以及交付后的增量

## 1. 文档范围

本文只列指挥部一侧的工作。引擎、契约与验收各有专文。指挥部是主产品：命令翻译、认知、敌军指挥官都在这一侧，引擎只认命令、只说真相。

## 2. 顺序与达成标志

### 2.1 M1：状态机与两份结构（1–2 周）

- 回合状态机：下令、结算、读报三个相位，规定所有模块的调用时序。它最先写，其余模块挂在上面。
- 情报记录：只追加，每条带出处、可信度、时效。
- 信念状态：每个敌军建制带估计位置、估计实力、置信度。
- 桩接通：命令编辑桩把一道纵队命令展开成引擎格式，事件进认知桩，随后弹出一条战报。

达成标志：下令到读报走通；同一组命令跑两遍结果一致。

### 2.2 M2：结构随引擎补全（1 周）

- 情报记录与信念状态跟随事件格式补齐字段。
- 档案写入交给主循环，指挥部只读报告。

达成标志：一局结束，指挥部侧只凭报告就能复述当时看到的战场。

### 2.3 M3：认知与敌军指挥官（2–3 周）

- 认知模块四步：过滤、延迟、失真、信念重算。
- 敌军指挥官：读自己的信念与两三个性格参数，按规则出命令，走同一套翻译与契约。

达成标志：真相与玩家所见两份记录能对照；敌军每个决策能回答当时信了什么；敌军读不到引擎真相。

### 2.4 M4：参谋与甲板（2 周）

- 参谋翻译器换成模板两级展开，附回执：参谋把理解反馈给玩家确认。
- 结构化追问：点选敌军建制弹出评估卡，含估计、置信度、出处。
- 界面只读信念，引擎状态对界面层不可导入。
- 存档与回放：状态、命令、随机记录齐备，各模块状态可序列化。

达成标志：同一局中途切换甲板层级，命令展开与战报投影衔接无误。

### 2.5 交付后：增量

- 大模型只接两处：战报润色与参谋对话。
- 敌军决策从规则换成可调参模型，性格参数从侧写卡全量导入。

达成标志：全量断言重跑，统计分布不漂移。

## 3. 后置代价

状态机与两份结构若不在 M1 定稿，后续每个模块的输入输出都要重接，M3 的认知管线会被迫先改结构再写逻辑。

档案写入若落到各模块自行处理，复盘时要逐个模块追写入点，M2 的定位能力也建不起来。

## 4. 纪律

- 引擎状态不可被界面直读，迷雾靠结构维持。
- 确定性检查进每次提交，比对不为空即停止合并。
- 大模型不进结算，只碰文本层。
