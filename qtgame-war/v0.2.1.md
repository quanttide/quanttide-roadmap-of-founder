# v0.2.1 — 档案与可复盘

**目标**：五卷档案齐备（命令、事件、情报、信念、决策），事件与报告在关卡处分开，一局打完能还原全过程并定位第一处偏离。

**依赖**：v0.2.0。

## 架构决定

- **档案只增不改**：写入点从本版锁死，只能由主循环写；结算返回补丁，关卡在相位表占一个位置。命令卷记曾想做什么，事件卷记实际发生了什么。
- **事件契约**：事件类型表先冻结（覆盖机动、接敌、战斗结果、损耗、补给、占领、战报生成，随机记录必须入契约），其余契约条款由它推导。命令字段一次定全（部队、动作、目标、路径约束、时限、中止条件），宁可先放超集不在后期补字段；单位番号与地图节点共用一套编号先冻结；所有随机带种子引用，事件流里不出现没有解释的随机性。本版是格式最后修订窗口，进入下一版改字段要两侧同步改桩。契约变更走版本号，确定性检查进每次提交，比对结果不为空即停止合并。
- **拒收语义**：命令在翻译预检失败、结算前提消失两种情况下失效，均生成事件并登记，不静默丢弃。
- **确定性签名**：研判、决断类模块显式接收回合号与随机子流，不读全局时钟或全局随机源。

## 验收

- 帝丘店全流程由脚本命令驱动跑完，五卷齐备并通过校验
- 同种子重跑，diff 零偏离，含情报卷
- 人为注入一处结算偏移，三分钟内指出第一处偏离的回合与相位（注错演练）
- 援军波次与胜负条件从想定读取，改 JSON 即改结局
- 金种子全绿进 CI；每个已实现机制至少一个专用夹具

## 风险与未达标处理

- 最大风险是战斗重构引入行为漂移 → 迁移前先录旧基线（输入命令与战损序列），重构后对基线，漂移要么解释要么修复
- 注错演练失败说明 diff 粒度不够，先补 diff 再继续
