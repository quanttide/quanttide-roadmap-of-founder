# v0.2.0 — 拆包与确定性（工程化线起点）

**目标**：引擎从 Flutter app 中拆出成为纯 Dart 包；同一命令流配同一主种子双跑零偏离——对局从「能玩」变成「可复算」。

**依赖**：v0.1.3（玩法形态稳定后再冻结结构，避免搬两次）。

## 架构决定

- **拆包**：Dart workspace 三层——`packages/engine`（纯 Dart，pubspec 不出现 Flutter，CI 检查）、`packages/studio`（现有 app 迁入）、`packages/tools`（命令行入口）。被迁走的模型文件删除，不留兼容层。迁移关系：`combat.dart` → 战斗结算；`game.dart` 拆为机动结算 + 世界状态；`battlefield.dart` 六角格辅助；阶段枚举 → 相位表；帝丘店三份 JSON 升格为引擎想定。
- **确定性**：主种子一次注入、按名字派生随机子流，未注册的取用点直接抛错；结算函数返回增量补丁，不直接改状态（变更可追踪、不必复制整棵树）。**引擎包禁用 `double`**，数值用整数（米、千分比）——Dart 的 double 跨平台不保证一致，这条从第一天执行并进 lint。
- **相位表**：友方决断 → 命令下发 → 机动结算 → 事件下发 → 回合归档；只点名各层公开入口，层内调度自理。控制器阶段分支退役。
- **想定格式 v0**：地图拓扑、初始部署、主种子，写版本指纹；硬编码地形参数迁入参数表。帝丘店作为第一个通过校验的想定（v0.1.1 已裁决龙王店为首个正式场景，帝丘店在本版仅作确定性验证的 fixture）。

## 架构落成检查（M1 开工前必须落定，每条写不成 lint 的不进入编码）

1. 事件、报告、命令三个类型的字段定稿 → 见 v0.2.1 事件契约
2. 世界状态与档案的写入口定稿：世界状态只有一个写入口（开局由想定初始化，结算时由补丁合并写入），结算返回增量补丁不直接改状态；档案只能由主循环写
3. 五条 lint 写成检查脚本：依赖方向（只准上层导入下层）、类型隔离（指挥部源码出现事件类型即失败）、子流白名单（随机取用点必须在注册的子流内）、档案写入权限、裸数值

达成标志：五条 lint 在空仓库上先跑通，再写第一行结算。纪律：设计原则要生效，得写成编译器或 lint 能拦住的规则。

## 数值参数落地（开工前一周，后续按需重跑）

- 一律给区间禁止点值；每个数字标来源性质（官方战史/回忆录/台湾战史/科普/纯估计）与置信度；允许回答记不得；战果类打七折到八五折，实员率默认 0.65–0.8
- 三视角交叉：解放军战史学者、国军战史学者、中立研究者独立抽取，交集即置信带；无交集取并集标低置信交作者裁决
- 作者裁决后卡片锁进参数文件；参数改动记指纹，分布漂移要能追到改了哪一个；未批准的数字不进引擎
- 达成标志：八到十个核心实体有区间、来源与置信度；基准局的历史结果落在参数带内；跑不出历史结果的参数做敏感性分析，怎么调都不对则问题在机制不在数字，回头改机制

- [ ] `replay` 重演 + `diff` 逐事件比对（输出第一处偏离的回合、相位、两侧原文）；验收由 diff 机械判断，肉眼不计

## 验收

- `engine` 包不依赖 Flutter（CI 查 pubspec）
- 同种子、同命令流双跑，事件卷逐字节一致（diff 零偏离）
- 更换主种子，diff 必现偏离并指出第一处
- 帝丘店想定 v0 通过校验，指纹落档
- 现有界面功能不回退（人工走一局）

## 风险与未达标处理

- 最大风险是浮点不确定 → 禁 double 用整数，第一天执行
- 随机取用点失控 → 子流未注册即抛错
- 未达标处理：双跑比对不过即冻结新功能只修确定性，不以临时容忍差异换进度
