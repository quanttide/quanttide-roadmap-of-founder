# qtgame-war 版本路线图

**更新**：2026-10-29（按版本号组织；取代原 code/ 四里程碑结构与 game/ 两篇专文，内容已折入各版本文件）

**定位**：本文档目录是 qtgame-war 的**唯一版本路线**。设计共识（核心机制为什么成立）在创始人档案仓 `qtgame-war/` 分区；版本怎么走以本文为准，代码仓 `src/studio/ROADMAP.md` 只管应用内步骤。

## 版本序列

| 版本 | 一句话目标 | 状态 |
|------|-----------|------|
| [v0.1.0](v0.1.0.md) | 通用引擎核心——战场模型 + CommandExecutor + 可注入战斗/胜负/地形，不绑任何剧本 | 进行中 |
| [v0.1.1](v0.1.1.md) | 龙王店剧本注入，跑通「矛盾 → 决心卡 → 翻译 → 执行 → 战报」竖切闭环 | 未开始 |

| [v0.2.0](v0.2.0.md) | 拆包（纯 Dart engine）+ 确定性（种子/子流/整数/同种子双跑零偏离），工程化线起点 | 未开始 |

两条线：**v0.1.x 玩法竖切**（先证明指挥官循环成立，形态不冻结）；**v0.2.x–v0.3.0 工程化**（玩法稳定后拆包定契约加认知，结构冻结）。前一段的验收未通过不进后一段。

## 跨版本纪律

- **核心检索不到剧本专名**：每个版本的验收都查这一条，含 JSON schema，不只 Dart 代码。核心 / 剧本边界清单见档案仓 `qtgame-war/constraints.md`。
- **确定性常青**：v0.2.0 起，同种子双跑零偏离在每版结束与每次引擎改动后必跑，不通过即回滚。
- **数值不进代码**：v0.2.0 起，新增数值一律进参数表并记指纹，lint 查裸数值。
- **档案只增不改**：v0.2.1 起，不引入改写档案的接口，写入点锁死在主循环。
- **大模型不进结算**：只碰文本层（战报润色、参谋对话）。
- **文档随代码走**：每版关闭时更新状态与受影响文档。

## 历史文档去向

原 `code/index.md`（四里程碑总纲）、`code/contract.md`（契约落地）、`code/command.md`（指挥部侧）、`code/acceptance.md`（验收工具链）、`game/index.md`（架构落成检查）、`game/params.md`（数值参数落地）已删除，内容按归属折入 v0.2.0 / v0.2.1 / v0.2.2 / v0.3.0。原「未决事项」四项裁决结果：首个正式想定 = 龙王店（v0.1.1）；指挥层级档数、M2/M3 串并行、大模型接入时点，随版本序列自然落定（大模型在 v0.3.0，串行推进），不再单列。
