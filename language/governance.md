## 怎么找

三条命令，各有边界：

```bash
qtfounder audit                                        # 每期一处，给人看
qtfounder language . --rules apps/qtfounder/src/cli/src/language/default-contract.toml --json
grep -rn "<词>" --include='*.md' .                     # 补漏
git log -S"<词>" --oneline                             # 查来历
```

体检只报一处，看总量要用第二条，滤 `"verdict":"real"`。扫描器一行只报第一处，同一行出现两次得靠 `grep` 补。`git log -S` 回答的是这个词是谁先用的：用户用过就该出库，不是硬改。

## 先谈出库的三类

有些词不该硬改，先讨论它还算不算禁用。

- 正常中文占多数。「依据」在章程里写「执行依据」，这是日常用法，换掉反而别扭。这类先数比例，过半就提修改章程与契约，把词移出。
- 词指真实对象。「账本」在澄清记录那里是东西的名字，不是修辞；财务文档已由语境声明放行。要动的是剩下那部分的名字，得连命令行、Skill 与档案一起改。
- 词是别的领域的术语。「证据」在认知行为疗法里指正反两面的事实，换成「凭据」会失真。这类要么缩小适用面，要么在契约里写明归属。

## 语境声明的边界

- 声明写文档主题，不写「文里出现过该领域的名词」。支付工程声明 `finance`，是因为它谈的就是账务对象。
- 一个文件只能声明一个领域。既谈工程又谈账务的，按主体选，选不出来的拆文件。
- 技术语境的词（接口、模块、参数）目前不在表里，先不标；等它们进表，再给工程文档补 `technology`。
- 对话里交代的语境工具读不到，那部分只能由人判，别指望闸门。
