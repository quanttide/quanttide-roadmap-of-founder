# 术语治理

清单与顺序。方法写成了 Skill：`language-govern`。规则本身在《汉语语用工程章程》与工具契约里，这里只记现在剩多少、先动哪个。

## 现在的位置

闸门只拦新增用词，体检每期报一处。两轮清完：「判定」53、「条目」52。剩下的候选 252 处，散在十六个词里。

## 怎么找

三条命令，各有边界：

```bash
qtfounder audit                                        # 每期一处，给人看
qtfounder language . --rules apps/qtfounder/src/cli/src/language/default-contract.toml --json
grep -rn "<词>" --include='*.md' .                     # 补漏
git log -S"<词>" --oneline                             # 查来历
```

体检只报一处，看总量要用第二条，滤 `"verdict":"real"`。扫描器一行只报第一处，同一行出现两次得靠 `grep` 补。`git log -S` 回答的是这个词是谁先用的：用户用过就该出库，不是硬改。

## 先谈出库的三类

有些词不该硬改，先讨论它还算不算禁用。

- 三成以上的命中是正常中文。比如「依据」在章程里写「执行依据」，这是日常用法，换掉反而别扭。这类词先数比例，正常用法过半就提修改章程与契约，把词移出。
- 命中指的是真实对象。「账本」几乎全指 clarify 的记录库，它是东西的名字，不是修辞。要动的是名字，得连命令行、skill 与档案一起改，不能只改文档。
- 命中是别的领域的术语。「证据」在认知行为疗法里指正反两面的事实，换成「凭据」会失真。这类要么缩小词的适用面，要么在契约里写明例外。

## 剩下的顺序

先动「产物」：十八篇，量大但语境清楚，一轮能带走 51 处。再动「口径」「落点」「合格线」「判据」，都是清楚的一对一替换。「账本」与「证据」放在改完名字、定好例外之后。

## 一轮怎么走

取真实命中、分语境定替换、脚本批量改并逐条断言、两套审计复查、分仓提交、路线图记一笔。逐步命令与坑写在 Skill `language-govern` 里。
