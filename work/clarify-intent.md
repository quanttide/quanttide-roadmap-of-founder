# 澄清意图

跟 AI 干活时那句「不对劲」通常没有留下痕迹：忍了、凑合改，下次再忍。这个工具把那个瞬间记下来——我以为它知道什么、它实际做了什么——当场给出一段能粘回对话的话；同一类差出现第二次，问你要不要立成一条规则。规则是你的，换哪个 AI 客户端都带着走。

命令行两个入口：名词 `qtfounder work intent` 看意图，动词 `qtfounder work clarify` 澄清一次。命令与字段见 quanttide-founder-lab 的 `docs/dev-guide/clarify-intent.md`。

## 目标

- 每次「不对劲」落成一条澄清记录，产出一段可直接粘回对话的提示词，而不是重写整条 prompt。
- 把「想起自己可以澄清」这一步从用户身上挪到工具上：信号出现时它先开口，用户只需要点头或给一句话。
- 同类偏差攒成规则，规则归用户本人所有，不绑在某个客户端上。

### 元目标

- 人对 AI 的判断留在自己手里，打开文件就能看能改，不交给厂商的黑箱记忆。

## 核心问题

- 用户愿不愿为「和 AI 少差一点」多花一步：主动召唤、写几行。主流产品都在消灭这一步，本工具成不成立取决于此；不回避，把它当筛选器。

## 已决策

- 名字叫「澄清意图」；对外不用「意图」「上下文差」「显性化」当卖点词，只说「你以为它知道的」和「它实际知道的」。
- 命令行就是「名词 + 动词」两个入口：名词 `qtfounder work intent` 是意图的视图（有哪些事、澄清过几次、哪些差重复了），动词 `qtfounder work clarify` 是澄清一次。开始前、过程中、结束后都走同一个动词，阶段不暴露成命令。
- 数据两层：intent（一件事，一句话任务）＋ 挂在它下面的澄清记录（原以为 / 实际做了什么 / 可粘回的话）。归类靠「实际做了什么」这一列，归一化后同样的出现 ≥2 次即为规则候选。
- 新开还是续记由动词的参数决定：给了任务就是新开一件事，不给就挂到最近的一件事上。
- HTTP API 是唯一真相，CLI 是薄客户端；skill 与将来的 MCP 适配都只是调用方。
- 规则要用户点头才落库，工具不生成规则文本；规则就是 `rules.md` 里的行，不单独建模。
- 触发分三级，由轻到重：过程中捕捉到返工信号主动点破一句（**只提示、不写库**）；任务收尾主动跑一次候选（**每次任务只提一次**）；用户召唤先定位对象再两问。同一类差一次会话只提一次，用户说「不用记」就不再提这一类。
- 澄清的形状是一个改字请求，不是问卷：先写出「原以为 / 实际 / 差」三行让用户改，用户只回「对」或改一行；定位不到对象就问一句「要澄清哪一段」，不空手发两问。用户在写分析、写文档、推方案时不打断——那是产出，不是返工。
- 写库只有两条路：用户点头回应提示，或用户在消息里已经把「原以为 / 实际做了什么」说清楚（此时直接记一条并回执，不再追问）。其余一律不写。
- 核心指标只有一个：生成的提示词被粘回对话的比例。比例低就改追问的引导，不加功能。
- 第一版不做：向量检索、多用户、同步、MCP 适配、自动生成规则、无信号的持续监听（主动触发只认明确信号，不做情绪检测）。

## skill 怎么走

三级触发，重的在后：

**A · 过程中主动点破（不写库）**。命中任一信号就一句话点破，不当场打断手头的活：同一个要求用户说了第二遍；用户话里出现「又是这样 / 我又说了一遍 / 不是这个意思 / 别再」；同一处产出被连改三次；agent 自己发现同类错误在本会话重复（又铺陈、又漏验收）。只说一句「这像是你说的那类差（原以为 X / 实际 Y），要不要记一条？」，不解释、不展开。

**B · 收尾主动复盘**。任务交付时跑一次 `qtfounder-lab work intent --json`，当前 intent 有 count ≥ 2 的候选就问一句「这类差第 N 次了，要不要立规则？你给一句话」。每次任务只提一次。

**C · 显式召唤 `/clarify-intent`**。召唤不等于已有对象：先从上下文认出是哪句话、哪个动作、哪次返工，认出就直接写出三行让用户改；认不出就问一句「要澄清哪一段」；对象明确但两行还不清，才问：

1. **定位上下文差**：你原本以为它知道 / 会做什么？它实际做了什么？两问必须落到具体行为，不接受「它就是不行」——概括是情绪，不是信息；答得笼统就追问一次「举它刚才那句话或那个动作」。
2. **生成提示词**：`prompt` 省略，由工具按两问拼模板（不给 agent 编话术的空间）。

```text
我原以为「【原本预期】」。
它实际做了「【实际行为】」。
请按我原以为的重做一遍，把这两条当约束。
```

**节流**：同一类差一次会话只提一次；用户说「不用记」则该会话不再提这一类；A 与 B 都不写库，写库只走两条路——用户点头，或用户已把两问答案说清楚（此时直接记并回执）。规则文本永远是用户的话，点头才落 `rules.md`。
