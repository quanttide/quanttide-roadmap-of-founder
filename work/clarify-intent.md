# 澄清意图

跟 AI 干活时那句「不对劲」通常没有留下痕迹：忍了、凑合改，下次再忍。这个工具把那个瞬间记下来——我以为它知道什么、它实际做了什么——当场给出一段能粘回对话的话；同一类差出现第二次，问你要不要立成一条规则。规则是你的，换哪个 AI 客户端都带着走。

命令行两个入口：名词 `qtfounder work intent` 看意图，动词 `qtfounder work clarify` 澄清一次。命令与字段见 quanttide-founder-lab 的 `docs/dev-guide/clarify-intent.md`。

## 目标

- 每次「不对劲」落成一条澄清记录，产出一段可直接粘回对话的提示词，而不是重写整条 prompt。
- 同类偏差攒成规则，规则归用户本人所有，不绑在某个客户端上。

### 元目标

- 人对 AI 的判断留在自己手里，打开文件就能看能改，不交给厂商的黑箱记忆。

## 核心问题

- 用户愿不愿为「和 AI 少差一点」多花一步：主动召唤、写几行。主流产品都在消灭这一步，本工具成不成立取决于此；不回避，把它当筛选器。

## 已决策

- 名字叫「澄清意图」；对外不用「意图」「上下文差」「显性化」当卖点词，只说「你以为它知道的」和「它实际知道的」。
- 命令行就是「名词 + 动词」两个入口：名词 `qtfounder work intent` 是意图的视图（有哪些事、澄清过几次、哪些差重复了），动词 `qtfounder work clarify` 是澄清一次。开始前、过程中、结束后都走同一个动词，阶段不暴露成命令。
- 数据两层：intent（一件事，一句话任务）＋ 挂在它下面的澄清记录（原以为 / 实际做了什么 / 可粘回的话）。归类靠「实际做了什么」这一列，归一化后同样的出现 ≥2 次即为规则候选。
- 新开还是续记由动词的参数决定：给了任务就是新开一件事，不给就挂到最近的一件事上。
- HTTP API 是唯一真相，CLI 是薄客户端；skill 与将来的 MCP 适配都只是调用方。
- 规则要用户点头才落库，工具不生成规则文本；规则就是 `rules.md` 里的行，不单独建模。
- 核心指标只有一个：生成的提示词被粘回对话的比例。比例低就改追问的引导，不加功能。
- 第一版不做：向量检索、多用户、同步、MCP 适配、自动生成规则、被动触发。

## 待决策

- 数据落点：server 侧 SQLite 单库（多端共享、好查询），还是第二大脑 `data/context/<集>/intention/` 的 Markdown（打开就能看能改、随仓库迁移）。两者不能同时满足，卡在这条没选。

## skill 怎么走

显式召唤 `/clarify-intent`，不猜意图、不自动触发，用户没召唤就什么都不做。两步：

1. **定位上下文差**：你原本以为它知道 / 会做什么？它实际做了什么？两问必须落到具体行为，不接受「它就是不行」——概括是情绪，不是信息；答得笼统就追问一次「举它刚才那句话或那个动作」。
2. **生成提示词**，套模板：

```text
刚才你的回答偏在【实际行为】，我需要的是【原本预期】。
差异在于【上下文差】。
接下来请【具体修正指令】。
```

记下来之后，同一类差出现第二次，skill 在末尾提一句「这类差是第 2 次出现了，要不要写成一条规则？」——点头才落 `rules.md`。第一版不自动提炼规则，只做候选标记。
