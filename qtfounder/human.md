# human 路线图

绩效观测：不打分，只对账。回答「我这周干了什么、为什么干」，产出是创始人的判断存档与主线叙事，不是考核表。方向已由创始人定案（2026-10-30），依据是 p02 实验首周运转（quanttide-human-lab `examples/performance/`）与绩效正本（profile 仓 `quanttide-founder/performance/`，叙事沉淀去向为宣传册体系）。本节只记顺序与验收，不记设计争论。

## 设计定案

**核心动作是校准，不是观测**（2026-10-30 首周实证）：推测无业务上下文必错——qtcloud 首轮弃置/搁置两猜全错，创始人一句话「功能迁往专用平台、主站工作台定位未定」纠正。观测机器迟早同质化，值钱的是「AI 推测 + 人一句话校准」这个循环，以及它攒出的判断存档；校准历史成为下一周推测的上下文，工具按人变准，档案按人增值。

循环五步：拉产出（GitHub；后接飞书、文档）→ 语义解读 + 业务目的推测 → 用户逐条一句话校准（对/错/改写）→ 校准句按业务线沉淀（线是文件、天是行）→ 主线与叙事自动生成。

以下红线是定案，来自 p02 首轮设计偏差（2026-10-30 反思归档），不因需求回炉：

- 不做考核打分、不做提交数仪表盘——git 事件是产出的传播半径，不是产出本身（首周 1827 条提交中四成为传播与同步）
- 报告不带评价词，意义只能由用户读出
- 校准句只能是用户的话，AI 只出推测
- 「人」的工作（带教、交底、考核）不在代码观测范围（散在飞书），口述补入，不视为缺席

## 范围：MVP Skill

- [ ] `human` 组一条 Skill：拉本周产出 → 生成语义解读与业务目的推测清单 → 接收「对/错/改写」→ 校准句追加到线文件
- [ ] 产出走事件不走现拉：真产出（release、日记落盘、Skill 发布）由产出端 XADD 推上本机总线（infra 的 Redis Streams，接法见 CLI 仓 user-guide/infra/event-bus.md），Skill 从消费组取积压——传播动作（指针同步、分发）不推，首周四成噪音从源头就不产生；危机周没空校准，事件在队里不丢，跳过那周在队列里天然留痕
- [ ] 上下文注入：线文件历史作为后续推测的上下文——越用越准的机制本体
- [ ] 命令面与命名随 v0.1 收口定，不随当前节奏漂移

## 验证：dogfood 一个季度

- [ ] 连续运转 8–12 周，每周校准句入 profile 仓绩效正本
- [ ] 阶段 4 闭环（p02）：季度初清单按线列，季度末按线对账——观测支撑的事前断言比拍脑袋的断言更准
- [ ] 主线报告与宣传册素材作为副产品自然出现（首周先例：三句校准长成商业计划开篇段）

达成标志：季度对账时创始人能指着档案说出「这个季度主线是什么、依据哪几周的校准句」，且素材直接进宣传册体系「商业策划」模块。

## 二期：入口与数据源

- [ ] qtcloud-lite 小程序推 digest + 一句话校准——media 排版管道供内容
- [ ] 飞书数据源接入——否则「人」的线永远只靠口述，观测范围缺一半

## 不做

- 面向管理者的监控视图：判例是「王在法下」，工具是被考核者的自观测，不是上级的望远镜
- 自动写结论：意义断言权归用户（qtcloud 两猜全错是判例）
- 组织级横向对比：档案是个人判断存档，不是排名素材

## 顺序理由与后置代价

先 Skill 后小程序：循环的价值在校准质量，入口形态不影响验证；循环跑熟了，入口才知道推什么。

先自己后对外：没有一个季度自己的档案，对外讲的是理论不是案例——media 的出生法同款（先内部摩擦、后市场）。

后置代价：跳过 dogfood 直接做产品，会做出又一个提交数仪表盘——p02 首轮偏差就是这么发生的，代价已归档在 lab 仓 `2026-10-30-设计偏差反思.md`。
